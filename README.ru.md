# FuseDB

[![Go](https://img.shields.io/badge/Go-1.25+-00ADD8?style=flat&logo=go)](https://go.dev/)
[![License](https://img.shields.io/badge/License-MIT-green?style=flat)](./LICENSE)

Встраиваемая key-value база данных для горячего изменяемого состояния.

[English](./README.md)

## Производительность

Apple M4, `darwin/arm64`, значения по 128 B, 64K засеянных ключей, кэш 5 MB у
обоих движков. Pebble работает в режиме `NoSync` — это baseline по задержке, а
не durable-запись. Разброс по 3 прогонам.

| Операция | FuseDB | Pebble (NoSync) |
|---|---:|---:|
| Чтение (64K ключей) | `1.06-1.13µs` | `4.25-4.39µs` |
| Запись | `1.03µs` | `0.83-0.88µs` |
| Открытие + первое чтение | `7.4-7.8ms` | `26.3-26.6ms` |
| Inc (атомарный счётчик) | `407-482ns` | — |

На записи Pebble быстрее. FuseDB меняет это на задержку чтения и время старта —
именно под такую нагрузку он и рассчитан: горячее состояние, которое постоянно
читают и которое должно быстро подниматься после перезапуска.

### Write amplification

Байт, реально записанных на диск, на байт пользовательских данных; merge после
каждых 4000 ключей. `один лист` — всё пространство ключей в одном сегменте;
`с делением` — листья делятся на 1 MiB.

| Ключей | User MB | Один лист | С делением | Листьев |
|---:|---:|---:|---:|---:|
| 20K | `2.82` | `3.33x` | `1.78x` | 3 |
| 40K | `5.65` | `6.11x` | `2.01x` | 6 |
| 80K | `11.29` | `11.66x` | `2.10x` | 12 |
| 160K | `22.58` | `22.76x` | `2.07x` | 23 |

Единственный сегмент приходится переписывать целиком на каждом merge, поэтому
его амплификация растёт вместе с базой. Деление удерживает merge внутри одного
листа, и амплификация остаётся постоянной, пока данные растут в 8 раз.

Воспроизвести: `go test ./benchmarks/oneleafdb -run TestWriteAmplification -v`

## Установка

```bash
go get github.com/uchebnick/fusedb
```

## Использование

```go
import "github.com/uchebnick/fusedb/pkg/fusedb"

db, _ := fusedb.Open(fusedb.Options{
    Dir:       "/tmp/db",
    CacheSize: 5 << 20,
    MergeSize: 5 << 20,
})
defer db.Close()

db.Put([]byte("key"), []byte("value"))
db.Inc([]byte("counter"), 1)
value, found, _ := db.Get([]byte("key"))
```

## Архитектура

- Упорядоченное по ключам дерево листьев; лист владеет своим сегментом и буфером
- Lock-free skiplist буфер
- Иммутабельные сегменты с LZ4 компрессией
- WAL с восстановлением после сбоя и групповым коммитом

Лист делится, когда перерастает `MaxLeafSize`, поэтому merge переписывает один
лист, а не всю базу. Именно это удерживает write amplification постоянной по
мере роста данных.
